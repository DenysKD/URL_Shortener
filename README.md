# URL Shortener

Вебсервіс для скорочення довгих URL-адрес. Користувач реєструється, створює коротке
посилання для будь-якого валідного URL і отримує статистику переходів. Перейти за
коротким посиланням може будь-хто, навіть незареєстрований користувач.

## Технологічний стек

- Java 25, Spring Boot, Spring Data JPA, Spring Security
- PostgreSQL, Flyway (міграції)
- JWT (авторизація)
- OpenAPI 3.0 / Swagger UI (документація API)
- JUnit 5, Mockito, Testcontainers (тести)
- Docker, docker-compose
- GitHub Actions (CI)

## Версіонування API

Усі ендпоінти версійовані за схемою `/api/v1/...`:

- `POST /api/v1/auth/register` - реєстрація
- `POST /api/v1/auth/login` - автентифікація, повертає JWT
- `POST /api/v1/urls` - створити коротке посилання (потрібен JWT)
- `GET /api/v1/urls` - усі посилання поточного користувача (активні та прострочені)
- `GET /api/v1/urls/active` - лише активні (термін дії ще не минув) посилання
- `PUT /api/v1/urls` - перегенерувати коротке посилання
- `DELETE /api/v1/urls` - видалити посилання
- `GET /api/v1/urls/{shortUrl}` - перехід за коротким посиланням (публічний доступ,
  не потребує авторизації)

Після запуску документація доступна на `/swagger-ui.html`
(специфікація - `/v3/api-docs`).

## Змінні оточення

Приватні значення (`DB_PASSWORD`, `JWT_SECRET`) не мають дефолтів у коді застосунку.
Їх потрібно передати через змінні оточення. Приклад - у файлі [`.env.example`](.env.example).

| Змінна              | Опис                                             | Значення за замовчуванням |
|---------------------|---------------------------------------------------|----------------------------|
| `DB_HOST`           | Хост PostgreSQL                                    | `localhost`                |
| `DB_PORT`           | Порт PostgreSQL                                    | `54321`                      |
| `DB_NAME`           | Назва бази даних                                   | `url_shortener`             |
| `DB_USERNAME`       | Користувач БД                                      | `postgres`                  |
| `DB_PASSWORD`       | Пароль БД                                          | обов'язково задати         |
| `JWT_SECRET`        | Base64 секрет для підпису JWT                      | обов'язково задати         |
| `JWT_EXPIRATION_MS` | Термін дії JWT-токена, мс                          | `86400000`                  |
| `APP_BASE_URL`      | Базова адреса застосунку (для формування посилань) | `http://localhost:8080`     |

## Запуск через Docker Compose

```bash
cp .env.example .env

docker compose up --build
```

Застосунок буде доступний на `http://localhost:8080`, БД - на `localhost:54321`.
Flyway-міграції застосовуються автоматично при старті.

## Локальний запуск без Docker

Потрібні: JDK 25, локальний PostgreSQL.

```bash
export DB_HOST=localhost
export DB_PORT=54321
export DB_NAME=url_shortener
export DB_USERNAME=postgres
export DB_PASSWORD=your_db_password
export JWT_SECRET=your_base64_jwt_secret

./gradlew bootRun
```

## Тести

Тестова база даних для інтеграційних тестів піднімається автоматично через
[Testcontainers] - для цього потрібен лише запущений Docker-демон, окремо
конфігурувати БД для тестів не потрібно.

Проєкт містить:
- Unit-тести (JUnit 5 + Mockito) для сервісів, валідатора, генератора,
  маппера, JWT.
- Slice-тести контролерів (MockMvc).
- Інтеграційний тест `UrlRepositoryIT` (`@DataJpaTest` + Testcontainers).
- Smoke-тест `UrlShortenerApplicationTests`.

```bash
./gradlew test
./gradlew jacocoTestReport
./gradlew check
```

Мінімальне покриття коду тестами (80%) перевіряється автоматично в
`./gradlew check` і в CI. Із розрахунку покриття свідомо виключені DTO, Entity,
конфігураційні та exception-класи - вони не містять бізнес-логіки.

## CI

Пайплайн у `.github/workflows/ci.yml` при кожному push/PR у `main`:
1. Збирає проєкт та запускає всі тести.
2. Перевіряє, що покриття коду тестами не нижче 80%.
3. Публікує звіти тестів і покриття як артефакти збірки.
4. Збирає Docker-образ, щоб переконатись, що `Dockerfile` робочий.

## Бізнес-правила

- Ім'я користувача при реєстрації має бути унікальним.
- Пароль - мінімум 8 символів, включно з цифрою, великою та малою літерою; зберігається
  у БД у зашифрованому вигляді (BCrypt).
- Створити коротке посилання може лише зареєстрований (авторизований) користувач.
- Оригінальне посилання перевіряється на коректність (валідний http/https URL).
- Коротке посилання генерується випадково, 6-8 літер/цифр, і є унікальним у межах системи.
- Якщо унікальний код не вдалося згенерувати за 5 спроб, API повертає помилку.
- Кожне посилання має дату створення, дату завершення терміну дії (20 днів від створення),
  лічильник переходів та автора (`user_id`). Дата створення не змінюється при редагуванні.
- Перейти за коротким посиланням може будь-хто, зареєстрований чи ні; статистика
  переходів оновлюється при кожному переході; перехід за простроченим посиланням
  повертає помилку (HTTP 410 Gone).
